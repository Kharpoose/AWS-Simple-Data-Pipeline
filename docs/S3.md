# S3

The pipeline uses a single bucket, split into prefixes rather than separate buckets. S3 doesn't have real folders — a "folder" is just everything sharing a common key prefix, which is why `failed/` won't even appear in the console until the first record actually fails validation.

## Layout

```
your-bucket/
├── incoming/          # raw sensor JSON, dropped here by the source
├── processed/         # enriched JSON, written by Lambda after validation
├── failed/            # raw copies of records that failed validation
└── athena-results/    # query output files, written automatically by Athena
```

## incoming/

Where sensor readings land as raw JSON files. An S3 Event Notification on this prefix is what triggers the Lambda function — it's the only prefix with a trigger attached.

## processed/

Holds the same file, same name, but enriched: `timestamp` (if it was missing), `status`, and `processedAt` added by Lambda. This is the prefix Athena reads from.

## failed/

A raw copy of any file that fails validation (a missing field, or temperature/humidity out of range). Nothing is transformed here — it's kept exactly as uploaded, so the original bad input can be inspected later instead of being lost.

## athena-results/

Not written by Lambda at all — this is where Athena automatically saves the output of every query you run (one file per execution, plus a small metadata file). It grows on its own as more queries are run, which is worth knowing so it doesn't come as a surprise later.
